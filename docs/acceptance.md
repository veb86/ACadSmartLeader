# Протокол приёмки issue #3

Статус: реализация этапов 1–4 подготовлена; приёмка в AutoCAD 2021 и 2025 **не выполнена**. В Linux-контейнере есть SDK .NET, отсутствуют AutoCAD, Windows desktop и лицензированный CAD-хост. GitHub Actions тоже не предоставляет AutoCAD. Поэтому подлинный `examples/demo.dwg`, снимки чертежа, поведение Undo/клонирования/регенерации, совместная загрузка с палитрой и результат ≤2 с остаются незавершёнными критериями. PR не следует сливать до их выполнения.

## Автоматические проверки

`tests/ACadSmartLeader.Core.Tests` использует закреплённый исходный Core и настоящую схему примера. Покрыты мотор/кабель и Power 7.5 → 11, формулы и точность ru-RU, пустые значения и defaults, ошибки, экранирование MText, отсутствие схемы/данных, порядок правил, неизвестные JSON-поля, кодек BobrovLeader v1, лимит UTF-8/хеш текста, планы обновления, приоритет привязки/неоднозначный GUID, геометрический допуск и очередь REGEN без повторного входа.

Windows CI компилирует net47, net48 и net8.0-windows, проверяет формулу из изолированной DLL каждого runtime, вставку параметров в обе полки WPF-редактора и структуру пакета. Сохранены рендеры [правил](screenshots/rules-dark.png), [их нижней части](screenshots/rules-dark-bottom.png), [редактора](screenshots/edit-light.png) и [настроек](screenshots/settings-dark.png). Приёмка внутри AutoCAD выполняется отдельно. Исходная схема дополнена включением `Device_Number` в шаблон MOTOR в `examples/demo-schema.json`, исходные файлы submodule не изменяются.

### Геометрия новых выносок (issue 11)

1. В пустом DWG со стандартным стилем мультивыноски загрузите плагин и [`leader-geometry.lsp`](../experiments/AutoCadAcceptance/leader-geometry.lsp) через `APPLOAD` из доверенной папки. Запустите [`leader-geometry.scr`](../experiments/AutoCadAcceptance/leader-geometry.scr) командой `SCRIPT`. Скрипт создаёт демонстрационную, обычную и групповую выноски. Для каждой ожидается `SL_GEOMETRY_OK` с именем команды. Проверка читает сохранённую точку стрелки, количество вершин линии и отдельную точку стыка с полкой.
2. Для сравнения с 0.1.3 запустите те же шаги в новом DWG на той сборке. Ожидаемый дефект — `SL_GEOMETRY_FAILED` и промежуточная вершина при выделении выноски. Сохраните снимок старой и новой сборки при одинаковом масштабе.
3. В новой сборке вручную запустите `SL_CREATE` и `SL_CREATE_GROUP`. Перетащите полку на другую сторону стрелки в предпросмотре. Проверьте, что стрелка остаётся на цели, а линия идёт прямо к полке. Повторите с повёрнутой ПСК и аннотативным стилем, затем сохраните и откройте DWG повторно. При отмене размещения новая выноска не сохраняется.
4. В чистом профиле проверьте запуск `SL_SETTINGS`, `SL_RULES` и `SL_UPDATE` из командной строки после автозагрузки bundle. В профиле со старой версией проверьте обновление по [инструкции](../installer/INSTALL.md#обновление-и-удаление). В обоих профилях проверьте отсутствие элементов ACadSmartLeader на ленте и в контекстном меню.

Запуск этого сценария и снимки требуют AutoCAD. В Linux и hosted CI AutoCAD отсутствует.

## Принятые решения

- Приоритет поиска соответствует разделу 9.3: сохранённый handle на геометрии → объект под стрелкой → единственный DEVICE_ID → отвязка. Подсказка WBLOCK в разделе 13 не меняет этот приоритет.
- Вне экрана и в неактивных листах применяется перебор пространства с отсевом по extents; создание сначала использует SelectCrossingWindow. Нет зависимости корректности обновления от видимой области.
- Сохранённый handle отвязанной выноски не обнуляется, чтобы восстановление удалённой цели через Undo работало.
- SL_SELECT_PROBLEMS выделяет объекты текущего пространства: AutoCAD PickFirst не может одновременно выделить объекты разных листов. All обновляет все листы; отчёт содержит проблемные handle.
- Этап 5 требует отдельных задач по явному тексту ТЗ. Поддержка свойств цели, мгновенного обновления и нескольких стрелок не заявлена.
